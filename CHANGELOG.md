# Changelog

## Не выпущено

### Добавлено

1. Подробный CLI-справочник `docs/CLI.md`: флаги, дефолты, профили, форматы,
   примеры и ограничения.

### Исправлено

1. Кадры NVDEC освобождаются сразу после копии в буфер энкодера: пропало
   предупреждение о locked frames и утечка поверхностей декодера.
2. Ошибка NVENC больше не превращается в тихий пропуск кадра: файл помечается
   failed, пакет продолжает со следующего. Копия в буфер энкодера повторяется
   один раз, ошибки кодирования, слива и дырки по PTS считаются фатальными.
3. Ошибки завершения энкодера и хвоста декодера больше не теряются молча.
4. Уменьшен трафик памяти: на каждом кадре зануляется только защитный хвост
   I/O-буферов, а не входной и выходной тензоры целиком.
5. Удалён неиспользуемый каркас очередей и пула буферов, а также лишние
   CUDA-стримы и event.
6. Ярлык «NisshokuSR CLI» больше не открывает пустой `cmd.exe`: запускает
   `nisshoku.cmd`, печатает help и оставляет консоль открытой.
7. `-o <файл>` теперь проверяет соответствие расширения и кодека: `.h265`
   требует `--codec-out hevc`, `.h264` — `h264`, `.av1` — `av1`; иначе
   ошибка до запуска, а не файл с чужим битстримом.
8. Raw-выход при `bframes > 0` теперь запрещён: для `quality*` используйте
   `.mkv`/`.mp4` или явно `--bframes 0`.

### Изменено

1. README дополнен новыми разобранными багами и отдельным списком известных
   ограничений.
2. Добавлен этот журнал изменений.
3. Portable можно собрать без готового engine: он копируется только при
   наличии в `testdata`. Модели, веса и engine в репозиторий не входят.
4. Профили `svfi` и `svfi-split` переименованы в `quality` и `quality-split`,
   флаг `--svfi` удалён. Старые имена больше не принимаются: используйте
   `--profile quality` или `--profile quality-split`.
